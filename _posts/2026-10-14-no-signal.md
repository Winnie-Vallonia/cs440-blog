## Key Idea

Routers can now send signals like queue length and link utilization straight to congestion control algorithms, but there's only so much room in a packet header, so we have to pick which signals are worth it.
The authors tackle this by using an improved version of Remy (R+) to learn the best algorithm they can for each set of signals, then comparing how they do.
What surprised me is the answer: these in-network signals usually land within 3% of plain end-to-end signals like RTT, and none of them is a clear winner.

## Critique

I liked that they used learned algorithms to judge the signals themselves instead of tying the results to one specific algorithm, and the BBR test where RTT did just as well made me trust the finding more.
What I wish they tested is what happens when these algorithms share a network with existing ones, since every scenario only has flows running the same algorithm.
I'd also want to see bigger topologies and cases like incast, where in-network signals might actually pull ahead.

## Connections

This made me think of Ware et al., who argue a new algorithm should be judged by the harm it does to existing traffic.
The authors even admit their modified BBR traded some fairness for lower delay, so I'd love to see that harm actually measured.
